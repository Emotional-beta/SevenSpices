# 《七荤八素》界面风格规范

> 版本：v2
> 文档状态：已定稿
> 定位：美术真源（**界面 / 局内玩法层**）。所有 UI、局内画面、图标与特效统一遵循本文档。
> 关系：人物立绘层（#191 淡彩）见《立绘风格规范》；叙事见《故事与世界观设计文档》。
>
> 变更（v2）：基准改为 **640×360 + 整数缩放**；字体选型落地（Fusion Pixel 12px）；确立**程序化像素皮肤（零贴图）**实现口径。

---

# 一、风格定义

- **统一风格**：Spellbook **#069 像素**（16-bit 像素表现）。
- **范围**：**全像素** —— 界面、局内场景、局内出现的角色、食材与道具图标、特效、装饰，全部为像素。
- **视觉特征**：清晰可见的像素栅格、纯色块 + 1px 描边、温暖调、亲和。
- **贯穿母题**：**青铜饕餮纹（兽面纹）**，以点阵纹样形式出现在面板与边框上。

> 依据：2026-09 风格横比（10 种风格）后选定 #069；`ui-01`（淡彩立绘嵌入像素面板）与 `ui-01b`（全像素）对照后，**确认采用全像素**，界面内不嵌入立绘。

# 三、配色

- **界面基色**：墨黑、青铜绿 / 氧化铜、暗金、赭石、石青
- **唯一强调色**：**朱砂红**（告警、超频、爆点）
- **汤面**：**统一淡金黄（鸡汤色）**，不做七层彩汤
- **七味标识色**（仅用于 HUD 与图标，不落在汤面）：
  酸=青柠绿、甜=琥珀金、苦=深褐橄榄、辣=朱砂红、鲜=乳白象牙、咸=月白银白、麻=青紫罗兰
- 目标：低饱和、克制、有"出土青铜器"的斑驳感。

# 四、栅格与缩放

- **窗口基准**：**640×360**。
  - 采用 640×360 的原因：1280×720 在 1080p 上做整数缩放只能取 **1×**（1080/720 = 1.5 向下取整）→ 四周黑边，故弃用。
- **最小单位**：**8 的倍数**——该规则适用于 **UI 尺寸与间距**（控件大小、内外边距、间隔、图标尺寸等对齐到 8px 栅格）。
  - **面板切角 / 圆角半径不受此限**：切角是像素观感问题，不是间距令牌，按视觉观感选取即可（现值为 `Radius = 6`、`RadiusSm = 4`）。
  - **HUD 内细粒度间距豁免**：HUD 里密排的短元素（如七味短条之间的间隔）允许小于 8（现用 4），以在 640px 基准宽内单行放下 7 个七味 chip；面板级尺寸与区块间距仍按 8 的倍数。
- **缩放**：**整数倍（integer）**——画面整体按整数倍放大，不做分数倍。
  - 1080p = **3×**、1440p = **4×**、4K = **6×**，均无黑边。
  - 屏幕尺寸不是基准的整数倍时会出现黑边，**属正常表现，不是 bug**。
- **Godot 设置（显式写入 `project.godot` 的键）**：
  - `display/window/stretch/mode = canvas_items`
  - `display/window/stretch/scale_mode = integer`
  - `rendering/textures/canvas_textures/default_texture_filter = 0`（Nearest）
  - `rendering/2d/snap/snap_2d_transforms_to_pixel = true`
  - `gui/fonts/dynamic_fonts/use_oversampling = false`
  - 关闭 Mipmap。
- **Godot 设置（依赖引擎默认值的键）**——不写入 `project.godot`，行为由引擎默认值保证：

  | 键 | 引擎默认值 | 现状 |
  |---|---|---|
  | `display/window/stretch/aspect` | `"keep"` | 生效值仍为 keep |
  | `gui/common/snap_controls_to_pixels` | `true` | 生效值仍为 true |
  | `rendering/2d/snap/snap_2d_vertices_to_pixel` | `false` | 生效值仍为 false（官方不建议与 `snap_2d_transforms_to_pixel` 同开） |

  - **提示**：运行 Godot 编辑器会重写 `project.godot` 并**自动剪掉数值等于引擎默认值的键**，这是**正常现象，不表示设置丢失**；无需（也无法）在文件里显式固定上表三项，如需核对以引擎默认值为准。
- **建议**：将 `Window.min_size` 设为 **640×360**，避免窗口被裁。
- **描边**：1px 深色描边，保证在暗底与亮底上都清晰。

# 五、字体

- **字体口径：全像素** —— 界面所有文本（含正文）统一使用像素字体，不再区分「正文用易读字体」。
- **已选型字体**：**Fusion Pixel（缝合像素）12px 比例 简体**。
  - 授权：**OFL-1.1，可商用**。
  - 导入参数：`antialiasing = 0`（None）、`hinting = 0`（None）、`subpixel_positioning = 0`（Disabled）。
- **字号**：必须取 **12 的整数倍**（现用 `FontBody = 12`、`FontTitle = 24`），以保证像素字形不被重采样破坏。
- **不采用**：Zpix —— 授权为商业单产品 USD 1000 且禁改禁再分发，不符合项目授权要求。

# 六、信息层级（常驻精简 + 按需展开）

- **常驻**：分数、倍率、七味条。
- **常驻 HUD 构成**（实现口径，`Scenes/Main.cs` → `BuildHud`）：HUD 固定顶部不随主体滚动，顶部为一条**青铜雷纹纹样饰带**，其下三行——①分数（标题字号）+ 倍率；②章 / 锅 / 碗数 / 阶段 + 右侧「详情」开合按钮；③七味短条（7 味一行）。核心进度与详情开关常驻，故一并列入 HUD。整块 HUD 高度实测 **112px**（预算 ≤112px）。
- **主体区块优先级**（实现口径，`Scenes/Main.cs` → `BuildUI`）：滚动主体按「当前需操作（食材候选 → 道具 → 推进按钮）→ 锅末流程（奖励 → 伙伴候选 → 已有伙伴 → 商店 → 路线）→ 信息（分数明细 → 食客 → 饕餮 → 结算文案 → 重新开始（投胎重来）按钮 → 金币）→ 档位与元操作（职业 / 存档读档）」排序（括号内为要素枚举，顺序即代码顺序），使本碗主操作落在首屏；状态变化时把当前激活的关键控件自动滚入视野（`ScrollContainer.EnsureControlVisible`），不逐帧强制滚动、不覆盖玩家手动滚动位置。
- **按需展开**（悬停 / 抽屉 / tooltip）：陈酿池、固化、物理状态「臭」、味道种类数、味道熵倍率、锅底等。以上按需项收在 HUD 下方的「详情」抽屉里（默认收起）。
- 原则：默认界面只回答"我现在多少分、还剩什么机会"；细节按需拉出。

# 九、生图技术约定

1. **模型**：调用 `generate_image` 时必须**显式指定** `model = "[次]gpt-image-2.5"`。
2. **尺寸**：界面用 `1536x1024`；`quality = high`；`n = 1`。
3. **文件名**：kebab-case 英文（如 `ui-01b-hud-allpixel.png`）。
4. **存放**：`generated-images/界面-像素成套/`。
5. **版本管理**：`generated-images/` 已加入 `.gitignore`，**图片不入版本库**。

# 十、技术实现口径（程序化像素皮肤）

- **零手绘贴图**：功能 UI 不依赖美术贴图，全部在 **C# 运行时**构建。
- **实现方式**：用 `Theme` + `StyleBoxFlat` 程序化生成皮肤——`CornerDetail = 1` + `AntiAliasing = false` 得到硬边 45° 切角，`BorderBlend = false`，边框宽度取偶数，尺寸对齐 8px 栅格。
- **纹样装饰层（M5）**：青铜母题（回纹 / 雷纹 / 云纹）由 **`PixelMotif` 纯几何算法生成**——整数像素 `DrawRect`、在 `unit×unit` 单元内生成横竖线段并按 `unit` 严格周期平铺，**零贴图、零手绘点阵**；`MotifBand` 是可复用的饰带 `Control`，可设纹样类型 / `Unit` / `Pen` / 朝向 / 颜色。已接入 HUD 顶部（低调雷纹带）。
- **代码位置**：`UI/Theme/`（`UiPalette`、`UiMetrics`、`PixelTheme`）、`UI/Controls/`（`PixelBar`、`PixelMotif`、`MotifBand`）。
- **自验证沙盒**：`Scenes/UiSandbox.tscn`（跑 1280×720 会截图并做像素级断言：皮肤边框色带、以及纹样的**存在性占比**与**相邻 `unit` 周期一致性**，均有 PASS / FAIL 与反证测试）。
